### Q1. 동시에 몇 개의 프로젝트가 적정한가?

복수 프로젝트 소속은 예외가 아니라 표준이다 — 조사에 따라 지식 노동자의 65~95%가 동시에 여러 팀·프로젝트에 속한다(O'Leary et al. 2011이 정리한 조사들 — 94.9%는 Martin & Bal 2006). 이 주제의 기준 이론(O'Leary et al. 2011)은 **역U 관계**를 제안한다: 소수의 동시 프로젝트까지는 생산성·학습이 오히려 올라간다(빈 시간이 메워지고, 시간을 배분해야 하니 일하는 방식이 정돈된다). 그러나 어느 지점을 넘으면 ==전환 비용과 일정 어긋남(한쪽이 다른 쪽을 기다리는 시간)이 이득을 잡아먹고 곡선이 꺾인다.==

주의: 이것은 **이론 모델**이고, 이후 실증 연구들은 맥락(프로젝트 유사성·역할·조직 지원)에 따라 엇갈린 결과를 보고한다(2024 리뷰). 즉 "정답 개수"는 문헌에 없다 — 확실한 것은 ==곡선의 오른쪽(과다 소속)이 실재한다는 것과, 꺾이는 지점이 사람·맥락마다 다르다는 것==이다. 자기 꺾임 신호: 어떤 프로젝트도 이번 주에 진전이 없고, 기다림·전환·현황 파악이 작업 시간을 넘어서기 시작할 때.

> [!example] 예시
> 프로젝트 2개일 때는 서로가 서로의 기분 전환이 되다가, 5개가 되면 "지금 뭐부터 봐야 하지"를 정하는 일 자체가 오전을 먹는다 — 앞쪽 오르막과 뒤쪽 내리막을 둘 다 겪어본 사람이 많은 이유다.

### Q2. 배분은 잘게 섞는 게 나은가, 굵게 나누는 게 나은가?

같은 총 시간이라면 **전환 횟수가 비용의 횟수**다. 전환마다 주의 잔류물과 재진입 비용이 발생하므로([[task-switching|전환의 뇌과학]]), 하루에 A·B를 잘게 오가는 것보다 굵은 덩어리로 나누는 편이 구조적으로 유리하다.

```d2
direction: down
fine: "잘게 섞기 — A·B·A·B·A" { class: bad }
cost: "전환 4회 = 잔류물·재진입 4회" { class: bad }
coarse: "굵게 나누기 — 오전 A, 오후 B" { class: good }
save: "전환 1회 + 프로토콜 1회" { class: good }
fine -> cost
coarse -> save
```

굵기는 두 단계가 실용적이다:

| 분할 단위 | 방식 | 맞는 경우 |
|---|---|---|
| 반일 분할 | 오전 A · 오후 B, 사이에 점심 완충 | 두 프로젝트 모두 매일 진도가 필요할 때 |
| 요일 테마 | 월·화 A, 수·목 B, 금 잡무·리뷰 | 반일 전환이 자꾸 무너질 때("눈에 밟힘"이 심할 때), 프로젝트가 3개 이상일 때 |

반일 분할이 무너지는 원인은 대부분 전환 절차 생략이다 — 먼저 [[task-switching|전환의 뇌과학]]의 프로토콜(복귀 계획·창 닫기·완충)을 적용해보고, 그래도 무너지면 전환 자체를 줄이는 요일 테마로 굵기를 올린다. **하루에 손대는 프로젝트는 최대 2개**라는 상한은 어느 굵기에서든 유지한다.

> [!example] 예시
> "오전만 A"가 3일 연속 실패했다면 의지를 탓하기 전에 굵기를 바꾼다: 이번 주는 월·화를 통째로 A에, 수·목을 B에 준다. 전환이 주 1회로 줄면 프로토콜 한 번으로 관리가 된다.

### Q3. 주간 운영 — 세운 계획을 실제로 이행하려면?

1. **주 시작 15분**: 프로젝트마다 "이것만 되면 이번 주는 진전"인 결과물 1개를 정한다. 전부를 조금씩이 아니라, 각각의 다음 매듭 하나씩.
2. **굵은 단위로 배정**: Q2의 굵기(반일 또는 요일)로 캘린더에 넣는다. 미팅이 많은 날은 딥워크 배정을 피하고 [[meetings|미팅이 있는 날]]의 조각 운영으로 전환한다.
3. **이행은 if-then으로 묶는다**: "수요일 오전이 되면 B 저장소를 열고 어제의 복귀 계획을 실행한다"처럼 상황-행동을 미리 묶은 **실행 의도**는 94개 실험 메타분석에서 목표 달성률을 중간~큰 폭(d = .65)으로 올렸다. 계획이 무너지는 지점은 대부분 "그때 가서 정하는" 빈칸이다 — 빈칸을 전날 채워둔다.
4. **어긋남을 기록한다**: 배정을 어긴 날은 자책 대신 어긋난 지점(시간대·트리거·프로젝트)만 적는다. 2주치면 패턴이 보이고, 다음 주의 굵기·배치를 그 패턴으로 조정한다([[daily-rhythm|하루의 리듬]]).

```d2
direction: down
w: "주간 계획 — 프로젝트별 결과물 1개"
b1: "블록 실행"
t: "전환 프로토콜" { class: good }
b2: "다음 블록"
log: "기록 — 어긋난 지점만" { class: muted }
w -> b1 -> t -> b2 -> log
log -> w: "다음 주 조정" { class: accent }
```

> [!example] 예시
> 기록 2주 후: "화요일 오후 B 예정이 매번 A로 샜고, 트리거는 점심 직후 A 슬랙 확인"이 보이면 — 처방은 의지가 아니라 화요일 점심 후 A 채널 알림 끄기 + B 첫 행동을 전날 적어두기다.

> [!info]- 연구 계보
> 원전 · **2006** Gollwitzer & Sheeran 메타분석(94개 실험, N>8,000) — if-then 실행 의도의 목표 달성 효과 d=.65 `확증`

출처: [Gollwitzer & Sheeran 2006](https://www.sciencedirect.com/science/chapter/bookseries/abs/pii/S0065260106380021)

### Q4. 예시 — 우선순위가 다른 4개는 한 주에 어떻게 배치하는가?

전제: **긴급 A·B, 분기 목표 C, 상시 D.** 우선순위는 A·B > C > D이지만, 넷 다 매주 진전이 있어야 하고 어느 것도 버릴 수 없다. 이 조합에 Q2·Q3의 원칙을 적용하면 배치 규칙은 세 개다.

1. **긴급은 가장 많이, 그러나 전부는 아니게.** 주 10개 반일 블록 중 6~7개. 긴급에 전부를 주면 C·D가 밀리고, 분기 말에 C가 새 긴급이 되어 돌아온다.
2. **분기 목표는 "보호 블록"으로 주 초·중반에 고정.** 긴급은 마감이 스스로를 지켜주지만 분기 목표는 밀려나는 게 기본값이다. C 블록은 ==옮길 수는 있어도 없앨 수는 없는 블록==으로 선언하고, if-then으로 진입을 자동화한다("수요일 오전이 되면 C 저장소를 연다").
3. **상시는 딥워크 블록을 쓰지 않는다.** 하루 최대 2개 규칙은 딥워크 프로젝트 기준이다 — 상시 운영 업무(D)는 저부하 고정 슬롯(슬럼프 존 30~45분)에서 매일 소화해, 딥워크 전환 비용을 아예 만들지 않는다.

| | 월 | 화 | 수 | 목 | 금 |
|---|---|---|---|---|---|
| 오전 딥워크 | A | B | **C 보호** | A | B |
| 슬럼프 존 (저부하) | D + 잡무 | D | D | D | D + 주간 리뷰 |
| 오후 딥워크 | B | A | B | **C 보호** | A 마무리·버퍼 |

- 블록 수: A 3.5 · B 4 · C 2 · D 매일 저부하 — 우선순위 순서 그대로, 넷 다 매주 진전.
- 하루 딥워크 프로젝트 2개 이하 유지(수: C·B, 목: A·C). 전환마다 프로토콜([[task-switching|전환의 뇌과학]]).
- 긴급이 정말 터져 C 블록을 침범해야 하는 주간: C를 **같은 주 안에서 재배치**한다(삭제 금지) — 금요일 오후 버퍼가 그 재배치 공간이다.
- 미팅이 많은 날은 그리드를 억지로 지키지 말고 [[meetings|미팅이 있는 날]]의 조각 운영으로 전환한다.

**수요일 하루 확대(9–6 기준)** — 반일 블록의 내부는 이렇게 생겼다. 휴식 배치는 [[rest-and-recovery|휴식의 뇌과학]]의 두 층 규칙(블록 안 미세 휴식 + 블록 사이 10분 이상 회복) 그대로다:

| 시간 | 내용 |
|---|---|
| 09:00–10:30 | **C 딥워크** (보호 블록) — 30분마다 일어나는 미세 휴식 포함 |
| 10:30–10:50 | 회복 휴식 — 화면 없이 |
| 10:50–12:00 | C 계속 → 끝에 복귀 계획 쓰고 창 닫기 |
| 12:00–13:00 | 점심 + 산책 — C→B 전환 완충 |
| 13:00–13:45 | **D 저부하 슬롯** + 잡무 (슬럼프 존) |
| 13:45–14:00 | 회복 휴식 — 화면 없이 |
| 14:00–15:30 | **B 딥워크** |
| 15:30–15:45 | 미세 휴식 |
| 15:45–17:00 | B 계속 |
| 17:00–17:30 | 주차장 메모 처리·메일 |
| 17:30–18:00 | 종료 루틴 — B 복귀 계획 + 내일 첫 행동 |

딥워크 합계는 4시간 안팎이다 — 9시간 중 나머지를 휴식·완충·저부하가 가져가는 것이 정상이고, 그걸 줄여 딥워크를 늘리려는 시도가 [[rest-and-recovery|휴식의 뇌과학]] Q1의 감쇠 구간을 만든다.

> [!example] 예시
> 흔한 실패 패턴: "C는 안 급하니 다음 주에" — 이것이 4주 반복되면 분기 말에 C가 긴급 3호가 된다. 보호 블록과 "삭제 금지, 재배치만" 규칙이 그 경로를 막는 장치다.

### Q5. 하루에 딥워크 3블록은 가능한가?

가능하다 — 단, 이 문서의 상한은 하루 딥워크 **프로젝트** 2개이지 **블록** 2개가 아니라는 것부터 분명히 한다. 3블록의 병목은 프로젝트 수가 아니라 시간이다. 9시간 근무에서 점심 1시간, 블록 사이 회복 3회(각 10~20분), 슬럼프 존의 저부하 슬롯, 종료 루틴을 빼면 딥워크에 남는 시간은 4~4.5시간이고, 이것을 셋으로 나누면 블록당 75~100분이다. 즉 ==3블록은 딥워크 총량을 늘리는 것이 아니라 같은 4시간을 두 덩어리 대신 세 덩어리로 자르는 것==이다. 회복과 완충을 깎아 5~6시간을 만들려는 시도가 [[rest-and-recovery|휴식의 뇌과학]] Q1의 감쇠 구간을 만든다 — 앉아 있는 시간은 늘고 산출은 줄어드는 조합.

3블록이 성립하는 조건은 셋이다.

1. **미팅이 0~1개인 날.** 미팅 하나가 블록 하나를 먹는다. 3블록 날은 미팅을 다른 날로 몰아낸 날이다([[meetings|미팅이 있는 날]] Q5의 배칭).
2. **프로젝트는 여전히 2개 — A·A·B 또는 A·B·B.** 세 블록을 세 프로젝트에 주면 전환이 2회가 되어 하루 2개 규칙이 깨진다. 예외는 세 번째 프로젝트의 블록이 "마무리 블록"(리뷰·정리·복귀 계획 수준의 얕은 완결)일 때뿐이다.
3. **세 번째 블록을 슬럼프 존(13~15시)에 두지 않는다.** 그래서 오전에 두 블록을 붙이거나(9–6), 오후 늦게 두 블록을 붙인다(10–7). 슬럼프 존은 그대로 저부하·이슈 창으로 둔다([[incoming-issues|중간에 들어오는 이슈]] Q3).

**9–6, 3블록 하루 (A·A·B)** — [[workday-design|고정 근무시간의 설계]] Q3의 9–6 골격에서 "미팅·협업 존"이 두 번째 딥워크 블록으로 바뀐 형태다:

| 시간 | 내용 |
|---|---|
| 09:00–10:30 | **딥워크 1 — A** (30분마다 미세 휴식) |
| 10:30–10:50 | 회복 휴식 — 화면 없이 |
| 10:50–12:00 | **딥워크 2 — A 계속** → 끝에 복귀 계획 쓰고 창 닫기 |
| 12:00–13:00 | 점심 + 산책 — A→B 전환 완충 |
| 13:00–14:30 | 저부하 존 — 이슈 창 1, 상시 업무(D), 리뷰 |
| 14:30–14:50 | 회복 휴식 — 화면 없이 |
| 14:50–16:30 | **딥워크 3 — B** (미세 휴식 포함) |
| 16:30–17:00 | 회복 + 이슈 창 2 |
| 17:00–17:30 | 잡무·주차장 메모 처리 |
| 17:30–18:00 | 종료 루틴 — B 복귀 계획 + 내일 첫 행동 |

딥워크 합계 260분(약 4시간 20분). 10–7이면 거울상이다: 오전 10:00–11:45 A 한 블록, 슬럼프 존을 지난 14:45–16:15와 16:35–17:45에 B 두 블록(A·B·B).

이 하루를 Q4의 주간 그리드에 넣으면 "오전 딥워크" 칸이 두 블록이 되는 것이고, 주 단위 배분 규칙(긴급 6~7블록, C 보호 블록, D는 저부하 슬롯)은 달라지지 않는다. 마지막 조건은 **기록**이다: 3블록 날의 세 번째 블록 산출이 2블록 날의 두 번째 블록보다 꾸준히 낮으면, 그 사람의 하루 딥워크 용량은 두 덩어리가 맞는 것이다([[daily-rhythm|하루의 리듬]] Q6). 3블록은 기본값이 아니라 기록으로 검증하는 옵션이다.

> [!example] 예시
> "오늘은 미팅이 없으니 A·B·C 하나씩" — 이것이 3블록의 흔한 오용이다. 전환 2회에 완충 2회가 들어가고, 셋 다 미완결로 끝나 잔류물이 세 방향으로 남는다. 같은 날을 A·A·B로 쓰면 A는 매듭을 짓고 B는 온전한 블록 하나를 받는다. C는 내일 오전 첫 블록으로.

## 셀프 테스트

> [!tip] 펼치기 전에 소리 내어 말하거나 손으로 직접 써보세요.

<details><summary>Q1. 역U 이론의 내용과 근거 상태는? "자기 꺾임"의 신호는?</summary>

소수의 동시 프로젝트까지는 생산성·학습 증가, 그 이상은 전환 비용·일정 어긋남으로 하락(O'Leary 2011 — 이론, 실증은 혼재). 신호: 모든 프로젝트가 진전 없음, 전환·현황 파악 시간이 작업 시간을 초과.

</details>

<details><summary>Q2. 굵은 분할이 잘게 섞기보다 유리한 이유와, 반일→요일로 굵기를 올리는 기준은?</summary>

전환 횟수 = 잔류물·재진입 발생 횟수이므로 같은 총 시간이면 전환이 적은 쪽이 유리. 전환 프로토콜을 지켰는데도 반일 분할이 반복해서 무너지면 요일 테마로 올린다. 하루 최대 2개는 유지.

</details>

<details><summary>Q3. 주간 운영 네 단계는? 계획 이행을 올리는 장치와 그 효과 크기는?</summary>

① 프로젝트별 주간 결과물 1개 ② 굵은 단위 배정 ③ if-then 실행 의도로 이행(d=.65) ④ 어긋남 기록으로 다음 주 조정.

</details>

<details><summary>Q4. 긴급 2 · 분기 1 · 상시 1을 한 주에 배치하는 세 규칙은?</summary>

① 긴급은 최다 배정하되 독점 금지(주 10블록 중 6~7) ② 분기 목표는 주 초·중반 보호 블록 — 재배치는 가능, 삭제는 불가, if-then으로 진입 ③ 상시는 딥워크 블록이 아니라 저부하 고정 슬롯(슬럼프 존)에서 매일 처리.

</details>

<details><summary>Q5. 3블록의 병목은 무엇이고, 총 딥워크 시간이 왜 늘지 않는가? 성립 조건 셋은?</summary>

병목은 프로젝트 수가 아니라 시간 — 점심·회복 3회·슬럼프 존·종료 루틴을 빼면 4~4.5시간이 남고, 3블록은 이것을 세 덩어리로 자르는 것이다(회복을 깎아 늘리면 감쇠 구간). 조건: ① 미팅 0~1개인 날 ② 프로젝트는 2개 유지(A·A·B / A·B·B) ③ 세 번째 블록을 슬럼프 존에 두지 않는다. 기록으로 검증해 세 번째 블록 산출이 낮으면 2블록으로 돌아간다.

</details>
